# [LS-07][中] 路由扫描把保留地址当成公网出口

严重程度：中

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-07 节。日志：[run1.stderr.txt](../run-logs/run1.stderr.txt)、[run2.stderr.txt](../run-logs/run2.stderr.txt)

## 现象

启动时的路由层级扫描在 `242.0.0.0/8` 停住，并把这一跳当成公网出口。该地址属于 `240.0.0.0/4` 保留段，不是可路由公网。界面上的 NAT 层级因此少算。回环、链路本地、组播也被另一套分类函数和这套函数判成不同的结果。

## 定位

- `modules/stun/network_nat_router.go`：`collectHops` 第 45 行（第 70–86 行见到 `public` 就停止，且不把这一跳记入结果）；`classifyIP` 第 93–105 行
- 对照 `modules/stun/stun_server.go`：`isNonPublicIP` 第 192–202 行。它认识回环、链路本地、组播和 CGNAT，`classifyIP` 不认识

## 根因

`classifyIP` 只把 RFC1918 标成 private、把 `100.64.0.0/10` 标成 cgn，其余全部是 public。`240.0.0.0/4`、`169.254.0.0/16`、`127.0.0.0/8`、`224.0.0.0/4`、`0.0.0.0/8` 都走 public 分支。

## 稳定复现步骤

1. 在会经过 `242.0.0.0/8` 的网络上启动程序，看路由扫描日志。审查机第一次是  
   `探测到公网出口: 242.14.30.107，终止扫描`，结果只有 `[{1 10.0.6.171 private}]`。第二次是 `242.2.26.193`，同样只剩一跳私网。
2. 直接调用 `classifyIP`，与 `isNonPublicIP` 对照：

```text
242.14.30.107  classify=public   isNonPublic=false
169.254.1.1    classify=public   isNonPublic=true
127.0.0.1      classify=public   isNonPublic=true
224.0.0.1      classify=public   isNonPublic=true
0.0.0.1        classify=public   isNonPublic=false
192.168.1.1    classify=private  isNonPublic=true
100.64.0.1     classify=cgn      isNonPublic=true
```

## 预期 vs 实际

预期：保留段、回环、链路本地、组播继续往下探，或标成未知并写进日志。NAT 层数不要停在这种地址上。

实际：扫描在第一跳保留地址结束。

## 建议修复方向

让 `classifyIP` 和 `isNonPublicIP` 共用一个函数，补上 `IsLoopback`、`IsLinkLocalUnicast`、`IsMulticast`、`IsUnspecified` 和 `240.0.0.0/4`。这类地址不要触发「已经到公网」。

## 证据摘要

两次启动日志里的「探测到公网出口」分别是 `242.14.30.107` 和 `242.2.26.193`。分类对照来自对 `classifyIP` / `isNonPublicIP` 的直接调用，临时测试已删除。
