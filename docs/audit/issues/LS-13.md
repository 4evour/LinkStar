# [LS-13][建议] 文档与构建入口和实现不一致

严重程度：建议

建议标签：`documentation`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-13 节。

## 现象

按 README 的开发者指南，ACME 实现是 lego，Linux 上可以用 `task build` 打当前平台的桌面版。仓库里两者都对不上。自签证书「全新安装自带一张」这件事和启动日志一致，不是缺陷；浏览器不信任自签，文档已经说明。

## 定位

- `README.md` 开发者指南的技术栈写「lego（ACME）」。`go.mod` 没有 lego。实现是 `modules/cert/acme.go` 的 `golang.org/x/crypto/acme`
- `README.md` 写 `task build` 构建当前平台桌面版。`Taskfile.yml` 的 `build` 依赖 `windows:build`，并用 `powershell -Command New-Item` 创建目录
- 自签有效期：本次启动日志写明到 2036-10-13，约 10 年。见 `logs/run1.stderr.txt`

## 根因

文档没有跟着 ACME 实现和 Taskfile 的 Windows 假设改。

## 稳定复现步骤

1. 在仓库里搜索 `lego`。它出现在 README，不出现在 Go 的 import。
2. 在这台 Linux 上执行 `task build`。审查时 `task` 未安装；即便装上，`Taskfile.yml` 里的 `powershell` 在这台机器上也不存在。
3. 空目录启动程序，日志有「已生成自签证书：0 个域名 + 4 个本机地址，有效期至 2036-10-13」。

## 预期 vs 实际

预期：README 的 ACME 库名和 Linux 构建命令与仓库一致。

实际：按 README 在 Linux 上不能用 task 完成发布构建；ACME 库名是错的。

## 建议修复方向

改 README，把 lego 改成 `golang.org/x/crypto/acme`。Linux 的 task 用 `mkdir -p`。桌面版继续说明需要 Wails，交叉编译不保证可用（`BUILD.md` 已经这么写了）。

## 证据摘要

`go.mod` 的 require 列表没有 lego。`modules/cert/acme.go` 第 24 行 import 的是 `golang.org/x/crypto/acme`。`Taskfile.yml` 第 34、45 行是 `powershell -NoProfile -Command "New-Item ..."`。
