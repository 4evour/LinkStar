# [LS-09][中] 搜索历史对未登录访问者公开

严重程度：中

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-09 节。

## 现象

搜索历史的写入需要登录，读取不需要。未登录的 `GET /api/home/search-history` 和公开的 `GET /api/home/config` 都会带上历史关键词。导航页一旦通过打洞或反代暴露，这些关键词对能访问 3333 的人可读。

## 定位

- `routers/home_routers.go`：`HomeRoutersPublic` 第 11–17 行，`home/config` 与 `home/search-history` 都在公开组
- `api/home_api/search_history.go`：`SearchHistoryGetView` 第 16–21 行，直接返回 `cfg.SearchHistory`
- `api/home_api/get_home_config.go`：`GetHomeConfigView` 第 41 行，把 `SearchHistory` 放进公开配置

## 根因

主页配置按设计公开，搜索历史跟着配置一起出去，另外还有一条专门的公开 GET。写接口在 `HomeRoutersProtected` 里。

## 稳定复现步骤

1. 登录后 `POST /api/home/search-history/add`，正文 `{"keyword":"nas-admin-password-hint"}`。返回「已记录」。
2. 去掉 `Authorization`，`GET /api/home/search-history`。
3. 再 `GET /api/home/config`，看 `data.searchHistory`。

## 预期 vs 实际

预期：历史只给已登录会话；公开主页配置不含 `searchHistory`。

实际：匿名 GET 返回 `{"code":0,"data":["nas-admin-password-hint"],"msg":"成功"}`。`/api/home/config` 的 `searchHistory` 是同一个数组。

## 建议修复方向

把 `home/search-history` 的 GET 挪进 `HomeRoutersProtected`。`GetHomeConfigView` 在未登录时把 `SearchHistory` 置空。如果主页只是要在这台浏览器里记住历史，放在浏览器本地，不要进公开 JSON。

## 证据摘要

审查时按上面三步在本机打过。关键词是为了复现故意写入的测试串，不是用户的真实搜索。
