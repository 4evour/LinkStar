# [LS-11][低] 修改密码没有失败次数限制

严重程度：低

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-11 节。

## 现象

登录失败有「3 分钟内最多 13 次」的限制。修改密码时校验旧密码不走这套限制。调用方已经持有有效 token，所以这不是未登录爆破；拿到 token 的人可以无限制试旧密码，试中后 `ChangePassword` 会轮换密钥并把原主人踢下线。

## 定位

- `modules/auth/store.go`：`ChangePassword` 第 150–170 行，旧密码不匹配时直接返回 `ErrWrongPassword`，不调用限制器
- 同文件 `Login` 第 109–116 行会调用 `globalLoginFailureLimiter.begin`
- `modules/auth/login_limit.go`：窗口 `loginFailureWindow = 3 * time.Minute`，上限 `loginFailureMax = 13`

## 根因

两处密码校验没有共用同一个限制器。

## 稳定复现步骤

1. 登录拿到 token。
2. 连续 `PUT /api/auth/password`，`oldPassword` 每次都错，`newPassword` 长度不少于 8。
3. 按代码，第 14 次仍返回「密码错误」，而不是登录接口那种「登录失败次数过多」，因为 `ChangePassword` 没有调用 `globalLoginFailureLimiter`。

本次审查没有把这 14 次请求的 HTTP 响应逐条存档。结论来自 `ChangePassword` 与 `Login` 的对照，限制器的数字来自 `login_limit.go`。

## 预期 vs 实际

预期：与登录共用同一限制器，触发时返回「请稍后重试」。

实际：`ChangePassword` 不记账。

## 建议修复方向

旧密码不匹配时走 `loginAttemptFailed`。限制器触发时和登录用同一句提示。

## 证据摘要

`Login` 在第 109 行调用 `begin`，`ChangePassword` 在核对旧密码的那段（约第 161–169 行）没有对应调用。
