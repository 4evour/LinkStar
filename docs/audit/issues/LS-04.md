# [LS-04][高] 公网 IP 探测失败仍报成功并清空已有地址

严重程度：高

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-04 节。

## 现象

STUN 服务器连不上时，公网 IP 探测函数仍返回 `nil` 错误，并把运行时里已经得到的公网 IP 写成空字符串，同时打一条「获取到的网络地址」成功日志。空地址不会通过 `EmitPublicIPChanged` 推进 DDNS，但门户和调度器读到的公网地址已经丢了。

另外，真正写回地址时只拒绝前缀 `10.`。`192.168.0.0/16`、`172.16.0.0/12`、`100.64.0.0/10` 会被当成公网。

## 定位

- `modules/stun/network_local.go`：`GetPublicIPInfo` 第 17–34 行。`GetPublicIP` 失败时 `fmt.Printf("获取真实公网ip失败%s", err)`（没有换行，也不进日志文件），然后 `return info, nil`
- `modules/stun/network_local.go`：`GetPublicIP` 第 48 行起，返回映射地址时不调用 `isNonPublicIP`
- `modules/stun/network.go`：`updateNetworkAddress` 第 65–99 行。第 79 行只判断 `strings.HasPrefix(addrInfo.PublicIP, "10.")`；第 90–91 行写回 `LocalIP` / `PublicIP`

## 根因

调用方只把非 nil 错误当成失败。空字符串不以 `10.` 开头，于是一次拨号失败被记成成功的空更新。若新旧地址不同，还会 `go updateNatRouter()`。

## 稳定复现步骤

1. 在 `stun` 包测试里把网络 DNS 模式设为跟随系统，先写入 `Runtime.Network.PublicIP = "203.0.113.10"`。
2. 调用 `GetPublicIPInfo("127.0.0.1:1")`。审查机出口绑在 `172.30.0.2`，这条连接不是立即拒绝，而是拨号超时。
3. 返回值：`err=<nil>`，`public=""`。stdout 出现  
   `获取真实公网ip失败连接STUN服务器失败: dial tcp4 172.30.0.2:0->127.0.0.1:1: i/o timeout`  
   没有换行。
4. 再调用 `updateNetworkAddress("127.0.0.1:1")`。实测 `ok=true`，`PublicIP` 从 `203.0.113.10` 变成空字符串。日志仍是  
   `通过 STUN 服务器 127.0.0.1:1 获取到的网络地址: LocalIP=172.30.0.2, PublicIP=`。

## 预期 vs 实际

预期：连接失败返回 error；已有公网 IP 保持不变；非公网映射地址沿用 `isNonPublicIP` 拒绝。

实际：失败被当成一次成功的空更新。

## 建议修复方向

`GetPublicIPInfo` 把 `GetPublicIP` 的错误返回给调用方，日志改走 logrus。`updateNetworkAddress` 在公网 IP 为空或 `isNonPublicIP` 为真时返回 false，不要写字段。删掉只判断 `10.` 前缀的分支。网络状态的锁见 LS-10。

## 证据摘要

上述调用的实测输出就是：`err=<nil> public="" local="172.30.0.2"`，随后 `updateNetworkAddress ok=true publicNow=""`。临时测试已从工作区删除，没有改业务代码。
