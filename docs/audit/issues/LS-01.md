# [LS-01][高] 内置 DNS 不可达时打洞模块永久起不来

严重程度：高

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-01 节。日志：[run1.stderr.txt](../run-logs/run1.stderr.txt)

## 现象

CLI 能听在 `0.0.0.0:3333`，管理页和导航页返回 200，但 STUN 模块初始化失败后不再重试。打洞调度器不会启动。日志把 DNS 超时说成 TCP 连接失败，17 台默认 STUN 服务器各一行，内容完全一样。

这次失败不是「没有 UDP、没有公网」。同一台机器上，系统 DNS 能解析 `stun.freeswitch.org`，对该主机的 TCP 3478 能连上，对 `stun.l.google.com:19302`、`stun.cloudflare.com:3478`、`stun.freeswitch.org:3478` 的 UDP Binding 也能拿到映射地址。

## 定位

- `modules/stun/outbound_iface.go`：`DefaultDNSServers`（第 308 行）、`dnsServers`（第 311–320 行）、`OutboundIface.resolve`（第 324 行）、`OutboundIface.lookupVia`（第 383 行）
- `modules/stun/stun_server.go`：`getSTUNServerDelay`（第 145–152 行）。第 151 行把底层错误换成 `TCP connection failed to be established`
- `modules/stun/init_stun.go`：`InitSTUN`（第 46–79 行返回错误，第 113 行的 `Scheduler.StartAll` 因此不会执行）
- `app.go`：`startModulesInBackground` 第 128 行 `initModule("STUN", stun.InitSTUN)`，全仓库只有这一处调用

## 根因

`dnsMode` 为空时不走系统 DNS，固定问 `114.114.114.114` 和 `119.29.29.29`。这两台从审查用的云主机 UDP/53 超时（各 2 秒），`8.8.8.8` 正常。`getSTUNServerDelay` 丢弃 `DialTCP` 的真实错误。`InitSTUN` 失败后那个 goroutine 结束，没有第二次初始化。

## 稳定复现步骤

1. 确认 `114.114.114.114:53` 与 `119.29.29.29:53` 的 UDP 查询超时，同时系统 DNS 能解析 `stun.freeswitch.org`，且对该主机 TCP 3478 或 UDP Binding 成功。
2. `go build -o /tmp/linkstar .`，在空目录执行该二进制。不要改 `config/stunConfig.json` 的 `network.dnsMode`（空字符串就是内置 DNS）。
3. 约 4–8 秒后日志出现 17 条 `TCP connection failed to be established`，然后是 `STUN 模块初始化失败：初始化 STUN 运行时失败: 没有可用的 STUN 服务器`。
4. `curl -s http://127.0.0.1:3333/api/version` 仍返回版本号。继续看日志，不会再出现 STUN 服务器或打洞服务启动。

对照：默认网络配置下 `OutboundIface.DialTCP("stun.freeswitch.org:3478")` 实测

```text
DialTCP elapsed=4.003s err=解析 stun.freeswitch.org 失败: lookup stun.freeswitch.org: i/o timeout
getSTUNServerDelay elapsed=4.002s err=TCP connection failed to be established
```

## 预期 vs 实际

预期：至少有一台 UDP 或 TCP 可达的 STUN 服务器被选中；DNS 失败时日志写出是哪台 DNS、哪台 STUN 超时；网络恢复后自动再探。

实际：列表里每台服务器都被标成 TCP 连接失败；`bestStun` 为空；打洞调度器不启动；HTTP 进程保持运行。

## 建议修复方向

`getSTUNServerDelay` 返回 `fmt.Errorf("连接 %s 失败: %w", srv, err)`。内置 DNS 都超时后退回系统解析器。服务器选择同时发 UDP Binding，不要只 `DialTCP`（本机对 `stun.l.google.com:19302` 就是 TCP 超时、UDP 成功）。`InitSTUN` 失败后按间隔重试，成功再 `StartAll`。

## 证据摘要

`run-logs/run1.stderr.txt`：17 条 `TCP connection failed to be established`，随后 `[error] STUN 模块初始化失败：初始化 STUN 运行时失败: 没有可用的 STUN 服务器`。同一次启动里 UPnP 为「未发现」，那是云主机没有网关，不是这条缺陷的原因。
