# [LS-10][中] 公网 IP 与 NAT 链路并发读写没有锁

严重程度：中

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-10 节。

## 现象

`Runtime.Network` 的公网 IP、本机 IP 和 NAT 链路被 STUN 更新器写入，同时被 DDNS 和调度器读取，中间没有互斥锁。和 LS-04 叠在一起时，别的 goroutine 可能读到刚被清空的地址，或者读到写了一半的切片。

## 定位

写：

- `modules/stun/network.go`：`updateNetworkAddress` 第 90–91 行写 `LocalIP` / `PublicIP`；`updateNatRouter` 第 112 行写 `NatRouterList`；`refreshOutboundIface` 第 136 行写 `LocalIP`

读：

- `modules/ddns/ddns_syncrecord.go`：`resolveIP` 第 147 行读 `stun.Runtime.Network.PublicIP`
- `modules/stun/scheduler.go`：第 649 行、第 712 行读 `Runtime.Network.PublicIP`
- `modules/stun/lookup.go`：第 88 行读 `Runtime.Network.PublicIP`

`modules/stun/enter.go` 里的 `STUNRuntime` 没有保护 `Network` 的锁。

## 根因

字符串和切片在一个 goroutine 里写、在别的 goroutine 里读。Go 内存模型里这是数据竞争。

## 稳定复现步骤

1. 一个 goroutine 循环调用 `updateNetworkAddress`，另一个循环读取 `stun.Runtime.Network.PublicIP`（`resolveIP` 的 STUN 分支就是这么读的）。
2. `go test -race` 会报告对 `PublicIP` 和 `NatRouterList` 的并发读写。

本次默认 `go test` 没有加 `-race`，正式测试输出里因此没有这条。结论来自上述读写点，不是来自一份 race 报告。

## 预期 vs 实际

预期：读到的永远是某一次写完的完整快照。

实际：没有同步。

## 建议修复方向

网络状态用 `RWMutex`，对外只返回拷贝。不要在持锁时做 STUN 或 traceroute。

## 证据摘要

见上面的符号和行号。没有单独的 `-race` 日志可以附上。
