# [LS-14][建议] 默认 STUN 测试绑定公网，离线必失败

严重程度：建议

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-14 节。日志：[go-test.stdout.txt](../run-logs/go-test.stdout.txt)

## 现象

`go test ./modules/...` 会失败，不是因为断言逻辑错了，而是三条测试要现场解析公网 STUN 域名。DNS 一超时，整个模块测试就是 FAIL。DNS 正常时它们又会真的对公网发探测，结果随出口 NAT 变化，不能当稳定回归。

## 定位

- `modules/stun/nat_type_test.go`：`TestNatType` 第 5–8 行，失败即 `t.Fatalf`
- `modules/stun/rfc5780_test.go`：`TestRFC5780UDP` 第 7–10 行，`TestRFC5780TCP` 第 32–35 行

同包里用假数据的 `TestClassifyTCPNatTypeEIMFallsBackToPortRestricted` 一类测试是通过的。

## 根因

测试直接调用 `selectRFC5780Server` / `DetectAndClassifyNat`，候选域名解析超时就判失败。没有 `integration` build tag，也没有环境变量开关。

## 稳定复现步骤

1. 执行  
   `go test -count=1 -timeout 30s -run 'TestNatType|TestRFC5780' ./modules/stun/`。
2. DNS 慢或被截断时，大约 4 秒后失败，错误是 `lookup <stun 主机>: i/o timeout`。
3. 审查时完整命令是  
   `go test ./api/... ./modules/... ./routers/... ./utils/...`  
   退出码 1。其余包为 `ok` 或 `[no test files]`，只有 `linkstar/modules/stun` 失败。

## 预期 vs 实际

预期：默认 `go test` 不访问公网。需要真网卡的探测放到 `//go:build integration` 或环境变量后面。

实际：这三条在普通测试列表里。本次把 `go test ./modules/...` 打成失败。

## 建议修复方向

解析和探测公网 STUN 的用例移出默认测试。`httptest` 覆盖不到的部分用 build tag 隔开。

## 证据摘要

`run-logs/go-test.stdout.txt`：

```text
--- FAIL: TestNatType (4.00s)
    nat_type_test.go:8: 启动时检测 NAT 类型失败: ... lookup stun.voipgate.com: i/o timeout
--- FAIL: TestRFC5780UDP (4.00s)
    rfc5780_test.go:10: selectRFC5780Server 失败: ... i/o timeout
--- FAIL: TestRFC5780TCP (4.00s)
    rfc5780_test.go:35: selectRFC5780Server 失败: ... i/o timeout
FAIL	linkstar/modules/stun	12.494s
```

同一次输出里还有一条转发测试打出的 error 日志（勾错 HTTPS 时的提示），那个测试本身是通过的，不要和这三条混在一起。
