# [LS-08][中] Web IP 来源不校验，失败页会被当成地址

严重程度：中

建议标签：`bug`

相关报告：[LinkStar 审查报告](../LinkStar-audit-report.md) 第 LS-08 节。日志：[run1.stderr.txt](../run-logs/run1.stderr.txt)

## 现象

DDNS 的 Web IP 来源把 HTTP 响应正文原样当作地址。状态码不是 2xx、正文不是 IP 时也不报错。内置的多个回显站结果互不一致时，谁延迟低就用谁，没有交叉验证。

审查机同一次探测里，五个 IPv4 回显站给出了五个不同地址。这台云主机的出口本身也不唯一（UDP STUN 映射同样分成多个地址），代码侧的问题是拿到什么就信什么。

## 定位

- `modules/ddns/ddns_syncrecord.go`：`fetchIPFromWeb` 第 397–421 行；`resolveIP` 的 `IPSourceWeb` 分支第 154–170 行
- 同文件 `initDefaultIPSources` 第 324 行起只按延迟排序，不要求各源结果一致
- 同文件 `parseFixedIP` 对自定义来源会 `net.ParseIP`，Web 来源不走这个检查

## 根因

`client.Get` 之后不看状态码，`TrimSpace` 后的正文直接返回。

## 稳定复现步骤

1. 用 `httptest` 返回 500 和正文 `<html>not-an-ip</html>`，调用 `fetchIPFromWeb(srv.URL, 4)`。
2. 实测 `err=<nil>`，返回值就是这串 HTML。
3. 启动程序看 DDNS 初始化日志。审查时同一次成功记录为：`34.196.179.219`（ipv4.getip.cc）、`18.233.210.77`（ifconfig.me）、`52.2.175.83`（myexternalip.com）、`54.236.146.182`（ipv4.ip.sb）、`34.228.201.179`（4.ident.me）。

## 预期 vs 实际

预期：非 2xx 或 `net.ParseIP` 失败则换下一个源；多个源结果不一致时不要更新记录，并在界面上说明。

实际：HTML 被当成 IP 返回；多个不同的 IPv4 都被记成「探测成功」。

## 建议修复方向

限制正文长度后 `net.ParseIP`，并核对地址族。状态码必须是 200。内置列表至少两个源一致才采用。用户自定义 URL 拒绝链路本地和云元数据网段。

## 证据摘要

临时测试日志：`status=500 body=html ip="<html>not-an-ip</html>" err=<nil>`。启动日志见 `run-logs/run1.stderr.txt` 里五条「IP源探测成功」，IP 各不相同。该测试已删除。
